`konfig helm` groups Helm chart management. It currently has one subcommand, `fetch`, which downloads every chart in the registry into the tarball cache ahead of time. Use it to warm CI caches so later `konfig crd` runs are independent of chart repositories. It does not pre-warm the render-time cache used by `konfig build`: `Helm.release` keys its tarballs by digest (see the caution below), so a build still pulls once per chart and digest.

## Usage

```bash
konfig helm fetch --all
```

## Flags (`fetch`)

| Name | Default | Description |
| --- | --- | --- |
| `--all` | `false` | Fetch all charts into the local cache. Required; without it the command prints `Specify --all to fetch all charts` and fails with `MissingAllFlag`. |

## Behaviour

- Reads the same configuration as `konfig crd`: registry directory (`KONFIG_CHARTS_DIR` / `charts`, default `infra/k8s-konfig/charts`), cache (`KONFIG_HELM_CACHE` / `helm.cacheDir`, default `.konfig/helm-cache`), minimum version (`KONFIG_HELM_MIN_VERSION` / `helm.minVersion`, default `3.16.0`), each falling back through env var, then the matching `konfig.json` field, then the built-in default. See [konfig.json](/konfig.ts/docs/cli/configuration/) for the precedence rule and [konfig crd](/konfig.ts/docs/cli/crd/) for the registry file format.
- Runs `helm version --short` and fails with `HelmVersionTooLow` when `helm` is absent or too old.
- For every registry entry prints `Fetching <chart>@<version>...`. When the registry entry has a `digest`, it pulls into a private temp directory, verifies the pulled tarball's digest with `Helm.verifyChartDigest`, and renames it into the cache under `<chart>-<version>-<digest12>.tgz`, skipping the pull entirely if that file already exists. When the entry has no digest, it runs `helm pull --repo <repo> <chart> --version <version> --destination <cache>` unless `<cache>/<chart>-<version>.tgz` already exists, and prints a warning that the render-time cache cannot reuse a plain-named entry.
- Ends with `Done. Cache at <cache>`.

<Aside type="caution">
Digest-suffixed cache entries (`<chart>-<version>-<digest12>.tgz`) are shared between `helm fetch` and render-time `Helm.release({ digest })`: fetching here with `--all` now warms the same cache slot a later `konfig build` reads from, so a build for a chart with a recorded digest does not re-pull it. `Helm.release` still hashes the cached tarball on every pull and every cache hit and fails with `HelmDigestMismatch` when the bytes changed. Charts with no recorded digest still cache under the plain `<chart>-<version>.tgz` name, which `Helm.release`'s digest-suffixed cache cannot reuse.
</Aside>

## Exit codes and errors

`MissingAllFlag`, `HelmVersionTooLow { required, found }`, `ChartRegistryError`, `ChartRegistryEntryDecodeError`, and process failures from `helm pull`.

## Example

```bash
KONFIG_HELM_CACHE=~/.cache/konfig-helm konfig helm fetch --all
```
