`konfig crd` turns the CRDs bundled with your Helm charts into TypeScript types so custom resources can be authored with editor support. `extract` writes the files; `verify` regenerates them into a temp directory and fails when the committed copies differ.

## Usage

```bash
konfig crd extract --release <id> | --all
konfig crd verify
```

## Flags (`extract`)

| Name | Default | Description |
| --- | --- | --- |
| `--release <id>` | unset | Chart release id to extract. |
| `--all` | `false` | Extract for every chart in the registry. |

One of `--release` or `--all` is required; passing neither prints `Specify --release <id> or --all` and fails with `MissingCrdFlags`. When both are given, `--release` wins and `--all` is ignored. `--all` with an empty registry prints `No chart definitions found in <dir>` and exits `0`. `verify` has no flags or arguments.

## What it reads

Both subcommands resolve their locations through the shared precedence chain (see [konfig.json](/konfig.ts/docs/cli/configuration/) for the table): an environment variable if set, otherwise the matching `konfig.json` field, otherwise a built-in default. The chart registry comes from `KONFIG_CHARTS_DIR` / `charts` (default `infra/k8s-konfig/charts`), the tarball cache from `KONFIG_HELM_CACHE` / `helm.cacheDir` (default `.konfig/helm-cache`), the output directory from `KONFIG_CRD_OUT_DIR` / `crd.outDir` (default `.generated/crd`), and the minimum Helm version from `KONFIG_HELM_MIN_VERSION` / `helm.minVersion` (default `3.16.0`). Outside a konfig project (no `konfig.json` found) only the environment variable and built-in default apply.

The registry is every `.ts` file in the charts directory whose name does not start with `_`. Each file is imported and scanned for an export carrying the `_konfigHelmRelease: true` marker; that object's `repo`, `chart`, `version`, optional `id` (defaults to the file name without `.ts`), and optional `digest` form one registry entry, decoded against strict patterns for chart names, versions, and `http(s)`/`oci` repo URLs so shell metacharacters never reach `helm`.

```ts title="infra/k8s-konfig/charts/postgres.ts"
export const chart = {
  _konfigHelmRelease: true,
  id: "postgres",
  repo: "https://charts.bitnami.com/bitnami",
  chart: "postgresql",
  version: "16.0.0",
  digest: "sha256:..."
}
```

## Behaviour

- Runs `helm version --short` first and fails with `HelmVersionTooLow` when `helm` is missing or older than the minimum.
- For each release: `helm pull --repo <repo> <chart> --version <v> --untar` into a scoped temp directory and read `crds/*.yaml` and `crds/*.yml`; then pull the tarball into the cache and run `helm template <chart> <tgz> --include-crds --no-hooks`. When the registry entry has a `digest`, the tarball is cached (and looked up first) under `<cache>/<chart>-<version>-<digest12>.tgz` via `Helm.verifyChartDigest`, the same slot `konfig helm fetch` and render-time `Helm.release({ digest })` use; without a digest it caches under the plain `<cache>/<chart>-<version>.tgz`, skipping the pull when that file already exists. Both CRD sources are parsed and de-duplicated by CRD name.
- For every `CustomResourceDefinition` the `openAPIV3Schema` of the first version that declares one is compiled with `json-schema-to-typescript` into an exported `<Resource>Input` type (the resource part of the CRD name, split on `-`/`_` and PascalCased), followed by a comment naming the CRD, group, and versions. A CRD with no schema in any version compiles as `{ type: "object", additionalProperties: true }`; a schema that fails to compile falls back to `Record<string, unknown>`.
- Output is `<outDir>/<id>.ts`, starting with the header line `// Generated by @konfig.ts/cli` (followed by a do-not-edit note on the same line). A chart without CRDs gets a stub file with the header, a `// No CRDs found in chart <chart>@<version>` comment, and `export {};`.
- `verify` regenerates every registry entry into a temp directory and compares byte-for-byte with `<outDir>/<id>.ts`. A committed file that is missing or lacks the generated header is reported as `<id>.ts (missing generated header)`; a registry with no entries prints a `No chart definitions found` note and exits `0`.

<Aside type="note">
The generated types are inputs for `Manifest.make` from `@konfig.ts/core`, which produces a `RawYaml` resource at render time. There is no runtime schema validation attached to them.
</Aside>

## Exit codes and errors

- `ReleaseNotFound { releaseId }` for an unknown `--release`; the message lists available ids.
- `MissingCrdFlags` when neither flag is given.
- `CrdDrift { drifted }` from `verify`, after printing `CRD drift detected in: ...` and `Run konfig crd extract --all to regenerate`.
- `HelmVersionTooLow`, `ChartRegistryError`, `ChartRegistryEntryDecodeError`, `CrdInputDecodeError`, `CrdExtractError { chart, cause }`.

## Example

```bash
KONFIG_CHARTS_DIR=infra/charts konfig crd extract --all
konfig crd verify      # in CI: non-zero exit when .generated/crd is stale
```
