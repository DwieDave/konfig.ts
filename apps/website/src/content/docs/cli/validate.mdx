`konfig validate <env>` renders the env exactly like `build` but keeps the result in memory. It then checks every YAML document structurally and, with `--strict`, hands the rendered tree to `kubeconform` for schema validation.

## Usage

```bash
konfig validate <env> [--strict] [--ignore-missing-schemas]
                      [--cluster <name>] [--k8s-version <ver>] [--flag k=v ...]
```

## Arguments

| Name | Default | Description |
| --- | --- | --- |
| `env` | required | Env name to validate. |

## Flags

| Name | Default | Description |
| --- | --- | --- |
| `--strict` | `false` | Additionally run `kubeconform -summary -strict <dir>` over the rendered manifests. Requires `kubeconform` on `PATH`. |
| `--ignore-missing-schemas` | `false` | Append `-ignore-missing-schemas` to the kubeconform invocation, for CRDs the bundled schema set does not know. |
| `--cluster`, `--k8s-version`, `--flag` | unset | Shared render flags, see [CLI overview](/konfig.ts/docs/cli/overview/). |

## Behaviour

- Structural validation parses each rendered file with the YAML parser and decodes every non-null document against a Kubernetes envelope schema: `apiVersion: string`, `kind: string`, optional string maps for `labels` and `annotations`, and DNS-pattern checks on names. `metadata.name` follows the RFC 1123 *subdomain* rule (lowercase alphanumerics, `-`, `.`, must start and end alphanumeric, max 253 chars) for every kind except `Namespace` and `Service`, which use the stricter RFC 1123 *label* rule (no dots, max 63 chars); `metadata.namespace`, when present, always uses the label rule regardless of kind. A `CustomResourceDefinition` named `sopssecrets.isindir.github.com` is valid under the subdomain rule; a `Service` or `Namespace` named with a dot is not. Deeper fields are left to kubeconform.
- Every issue is printed to stderr as `<file> (doc <n>) <path>: <message>`, naming the specific rule violated (e.g. `metadata.name '...' is not a valid RFC 1123 subdomain — ...` or `metadata.namespace '...' is not a valid RFC 1123 label — ...`); a YAML parse failure is reported as one issue for `doc 0`.
- On success it prints an `OK` line: `env '<env>': <n> file(s) pass structural validation`.
- `--strict` renders fresh in memory and stages the result into a scoped scratch temporary directory (cleaned up automatically when the command exits), then runs kubeconform against that directory. It no longer depends on a prior `konfig build` and never reads stale output from a previous build's output directory. `--k8s-version`, when set, both shapes your render (`ctx.k8sVersion`) and is forwarded to kubeconform as `-kubernetes-version <ver>`.
- Nothing is written to disk outside the `--strict` scratch directory, and the build cache is not consulted or updated.

## Exit codes and errors

- `StructuralValidationFailed { env, issueCount }` after any envelope issue; the issues are already on stderr.
- `KubeconformNotFound` when the binary cannot be spawned. The message reads `kubeconform binary not found`, asks you to install it for `--strict` validation, and includes the attempted command line (`kubeconform -summary -strict <dir> ...`).
- `KubeconformReportError { stdout, stderr }` when kubeconform exits non-zero; its output is included in the message.
- The same config, entry, and render errors as [konfig build](/konfig.ts/docs/cli/build/).

## Example

```bash
konfig validate prod
konfig validate prod --strict --ignore-missing-schemas
```
