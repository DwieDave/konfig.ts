Kubernetes links resources by plain strings: an env var names a Secret, a volume names a ConfigMap, a Service names a container port. `@konfig.ts/k8s` replaces those strings with branded types at every link, so a reference to something nobody created, or created in the wrong namespace, fails to type-check.

## The ref types

All refs are `string & { [Brand]: ... }`; the runtime value is the plain name and serializes to YAML unchanged.

| Ref | Type parameters | Produced by |
| --- | --- | --- |
| `SecretRef<N, K, Ns>` | name, key union, namespace | `Secret.make(...).ref`, `Secret.bind(...).ref`, `Environment.bind(...).members.X.ref`, `yield* Dep.Secret(name)` |
| `ConfigMapRef<N, K>` | name, key union | `ConfigMap.make(...).ref`, `yield* Dep.ConfigMap(name)` |
| `ServiceAccountRef<N>` | name | `ServiceAccount.make(...).ref`, `yield* Dep.ServiceAccount(name)` |
| `PvcRef<N>` | name | `yield* Dep.Pvc(name)`, `PvcRef.of(name)` |
| `BuiltImageRef<App>` | app name | `yield* Dep.Image(app)`, `BuiltImageRef.of({ app, registry, tag })` |
| `PortName<N>` | port name | `Port.make({ name, ... })`, `Port.ref(name)` |

`Secret.make` and `ConfigMap.make` infer `K` from the keys of `data` / `stringData`, so `EnvVar.fromConfigMap({ ref: featureFlags.ref, key: "NEW_UI" })` only accepts keys that exist. Renaming a key in the ConfigMap breaks every consumer at compile time.

Escape hatches exist for genuinely external resources: `SecretRef.of(name)`, `ConfigMapRef.of(name)`, `ServiceAccountRef.of(name)`, `PvcRef.of(name)`. They mint a ref without any provider, so use them only for objects managed outside konfig.ts.

## Enforcement points

The following inputs take a branded ref and reject a raw string:

- `EnvVar.fromSecret` / `EnvVar.fromSecretForPod` (`valueFrom.secretKeyRef.name`) and `EnvVar.fromConfigMap` (`configMapKeyRef.name`).
- `Volume.fromSecret({ ref })`, `Volume.fromConfigMap({ ref })`, `Volume.fromPvc({ claim })`.
- `imagePullSecrets: [{ name }]` on `Workload.web`, `Workload.cron`, `ServiceAccount.make`, and the pod spec inputs.
- `Ingress.tls({ secretName })` and the `tls` array of `Ingress.make` / `Workload.web`.
- `Port.ref` in probes (`httpGet.port`, `tcpSocket.port`, `grpc.port`) and in `Service` `targetPort`.

### Namespace match

`SecretRef` carries the owning namespace as its third parameter. `EnvVar.fromSecretForPod({ name, ref, key, podNamespace })` requires `ref`'s `Ns` to equal `podNamespace`, because the kube-apiserver only resolves `secretKeyRef` inside the pod's own namespace. Passing a ref bound in `"app"` to a pod in `"batch"` is a compile error. `EnvVar.fromSecret` is the unchecked variant for cases where the namespace is not known at the call site; `SecretRef.unsafeReNamespace` widens the slot when you have to.

### Duplicate env names

`Container.define` computes the pairwise intersection of the `name` literals in `env`. Two entries with the same name (for example a manual `EnvVar.value({ name: "DATABASE_URL" })` next to `...bound.envVars`, which already emits `DATABASE_URL`) produce a `_konfig_duplicate_env_names` hint: `Duplicate env name(s): "DATABASE_URL". K8s silently last-wins; rename one of the colliding entries or remove the manual valueEnv that shadows another producer.`

## Container.define and Workload.web

`Container.define` returns a `ContainerSpec<Ports, Mounts>` whose port-name and mount-name unions come from the `ports` and `volumeMounts` tuples. Probes on the same container, and Service ports on the enclosing `Workload.web`, are typed against that union.

<Snippet file="infra/modules/api.ts" startAt="      const apiContainer = Container.define({" endBefore="      return [...bound.manifests, workload]" />

`Workload.web` takes:

- `name`, `namespace`, optional `labels`, `annotations`, `reloader`.
- `deployment: { replicas?, containers, volumes?, imagePullSecrets?, serviceAccountName?, podLabels?, podAnnotations? }`.
- `service: { ports: ServicePortSpec<PortNames>[], type? }` where `targetPort` is a number or `Port.ref` of a port declared on one of the containers.
- `ingress?: { ingressClassName?, rules?, tls?, annotations? }`.

It renders `[Deployment, Service]` or `[Deployment, Service, Ingress]`, with `selector.matchLabels` fixed to `{ app: name }` and merged last into the pod labels so a colliding `podLabels` entry cannot desync the selector. `Workload.cron` takes `{ name, namespace, schedule, containers, concurrencyPolicy?, successfulJobsHistoryLimit?, failedJobsHistoryLimit?, volumes?, imagePullSecrets?, restartPolicy? }` and renders a private `ServiceAccount` plus a `CronJob`.

For anything outside those two shapes, use `Deployment.make`, `StatefulSet.make`, `Job.make`, `CronJob.make`, `Service.make`, and `Ingress.make` directly, as `infra/modules/worker.ts` does with `Deployment.make`.

## Rolling on secret change

A Deployment does not restart when a referenced Secret changes. Two options:

- `Workload.web({ reloader: "stakater" })` adds `reloader.stakater.com/auto: "true"`; `"stakater-strict"` adds `reloader.stakater.com/match: "true"` as well; `{ secrets: [...], configMaps: [...] }` emits the per-resource `secret.reloader.stakater.com/reload` / `configmap.reloader.stakater.com/reload` annotations. Requires Stakater Reloader in the cluster and rolls on in-cluster change.
- `hashSecretValues({ values, salt })` returns a SHA-256 hex digest of a `Record<string, Redacted<string>>` (netstring-framed, prefixed with a version tag and the salt). Put it in a pod annotation and the pod template changes whenever the values change at render time. Values are captured at build time only; a rotation between builds needs the reloader.

<Aside type="caution">
`hashSecretValues` is a change-detection fingerprint, not a cryptographic commitment safe to publish. The salt is non-secret and only stops the digest from being a pure function of the plaintext.
</Aside>
