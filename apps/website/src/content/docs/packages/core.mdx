`@konfig.ts/core` is the foundation the other konfig.ts packages are built on. It knows nothing about Kubernetes resource shapes; it provides the machinery that every package shares:

- the manifest carrier that wraps a value to be rendered (`Manifest`),
- the typed needs and provides that drive compile-time dependency tracking (`Dep`),
- the module factories that give a build a namespace and a target (`Module`),
- Helm chart rendering with digest verification (`Helm.release`),
- deterministic YAML serialization and a structural diff,
- and the `renderAllYaml` helpers.

Most projects work with the higher-level packages (`@konfig.ts/k8s`, `@konfig.ts/env`, `@konfig.ts/argocd`) and reach into core directly only for `Module.*`, `Dep.*`, and `Helm.release`.

## Install

```bash
bun add @konfig.ts/core
```

## Usage

A reusable module that creates a namespace and pulls a digest-verified Helm chart. `Module.fixedNs` pins the module to one namespace. `Application.target` (from `@konfig.ts/argocd`) turns the module into an Argo CD Application handle.

<Snippet file="infra/modules/postgres.ts" startAt="export const definePostgres" title="infra/modules/postgres.ts" />

Dependencies between modules are declared inside the build. Writing `yield* Dep.Secret("ghcr-pull")` records a typed need for that secret; some other module must satisfy it with `Dep.provideSecret("ghcr-pull")`. Nothing is checked at that point. The check happens when you compose modules at `AppOfApps.fromModules`; see [Dependency graph](/konfig.ts/docs/concepts/dependency-graph/).

## Surface

| Export | Purpose |
| --- | --- |
| `Manifest` | `make`, `concat`, `embedYaml`: the `Manifest<A>` carrier and its combinators |
| `renderAllYaml`, `renderAllYamlEffect`, `renderManifest`, `RenderContext` | Render manifests against a `RenderContext` (env, cluster, k8s version, `flags`) into multi-document YAML |
| `Dep` | Needs (`Secret`, `SecretValues`, `Namespace`, `Image`, `Application`, `App`) and `provide*` layers |
| `SecretRef`, `ConfigMapRef`, `PvcRef`, `ServiceAccountRef`, `BuiltImageRef` | Branded reference types (k8s constructs the non-secret ones; `BuiltImageRef` is also a value with `of`); `*RefName`, `*RefKeys` helpers extract the brand parameters |
| `Module` | `fixedNs`, `dynamicNs` factories; `Target`, `BuildContext`, `LiteralName` types |
| `Bundle`, `Compose` | Non-Argo module composition (`Bundle.define`, `Bundle.target`, `Bundle.fromModules`) and the type-level tracking of unmet needs behind every `fromModules` (`Compose.ResidualCheck`, `Compose.NoDuplicateProvides`) |
| `Helm` | `Helm.release({ repo, chart, version, digest, values, releaseName?, namespace?, extraOpts?, minVersion? })`: chart pull, SHA-256 digest verification, `helm template`; `cacheFileName`, `ensureChartTarball`, `assertMinVersion`, `timeout` for the CLI's shared cache |
| `Yaml` | `serialize` (stable key order) and `filenameFor` |
| `diffFiles`, `formatDiff`, `hasDifferences`, `parseYamlAll` | Structural YAML diff |
| `KonfigConfig`, `decodeKonfigConfigEffect` | Schemas and decoders for `konfig.json`; `ResolvedKonfigConfig` pairs the decoded config with its directory |
| `ImagesConfig`, `decodeImagesSync`, `decodeImagesEffect`, `imagesFor`, `requireImage` | Schema and lookups for `images.json` |
| `boundary`, `brand`, `unsafeCoerce` | Schema decode at boundaries; annotated escape hatches |
| `runProcessString`, `runProcessExit`, `runProcessCollect`, `runProcessWithStdin` | Subprocess helpers used by Helm and the secret backends |

## Errors

Core exports tagged error classes from `src/index.ts`. The render-time ones are grouped in the `AnyRenderError` union, which is the error type you see on every manifest's render and on the `fromModules` compositions built on top of core.

| Error | Meaning | In `AnyRenderError` |
| --- | --- | --- |
| `RenderError` | A render step failed; carries a message and an optional cause | yes |
| `BoundaryDecodeError` | Data at a boundary did not match the named schema | yes |
| `CrdExtractError` | Extracting CRDs from a chart failed | yes |
| `ImagesEnvMissing` | `images.json` has no entry for the requested env | no |
| `ImagesAppMissing` | `images.json` has no image for the requested app in that env | no |

<Aside type="note">
`Manifest<A>` does not carry dependencies in its own type. Per-kind tracking lives one level up, in the Effect `Layer`s that `Module` and `Application.define` compose.
</Aside>

## Requirements

- `effect@^4.0.0` as a peer dependency (Effect 4).
- `@effect/platform-node` and `yaml` are regular dependencies: `renderAllYaml()` needs the Node filesystem and subprocess services, so they install with the package.
- Runtime: Bun recommended; Node >= 23.6 works; Node 22.6 to 23.5 with `--experimental-strip-types`; `tsx` works.
