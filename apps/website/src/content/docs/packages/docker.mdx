`@konfig.ts/docker` generates Dockerfiles for the apps in a Bun or Node monorepo. You write one `docker.ts` spec next to each app and the package works out the rest: it resolves the app's transitive workspace dependencies and emits a Dockerfile that copies exactly those packages, so there is no hand-maintained `COPY` list to keep in sync. The output is a production multi-stage Dockerfile with `base`, `deps`, `builder`, and `runner` stages (plus a `prod-deps` stage when `runner.production` is set). If the spec has a `dev` block, it also emits a `Dockerfile.dev` made of the `base` and `dev` stages. The package stops at Dockerfiles: it does not build, push, tag, or sign images.

## Install

```bash
bun add -d @konfig.ts/docker
```

The base image tags come from the app's `package.json`. It must set `engines.<runtime>` and `engines.<package manager>`, for example `engines.bun`, or `engines.node` plus `engines.pnpm`. A missing runtime entry fails with `EngineVersionMissing`; the package manager version falls back to the root `packageManager` field. Values must be an exact version or a major(.minor) version such as `22` or `22.4`; ranges like `>=22` fail with `EngineVersionInvalid`.

## Usage

The API spec from the full-stack example. `runner.production` adds a stage that installs production dependencies for the target closure only.

<Snippet file="apps/api/docker.ts" startAt="export default Docker.app" title="apps/api/docker.ts" />

Render, write, or check the files with the CLI, then build with the monorepo root as the Docker context:

```bash
konfig docker preview apps/api   # render to stdout
konfig docker write apps/api     # writes apps/api/Dockerfile and Dockerfile.dev; refuses to overwrite files without the konfig header unless --force
konfig docker diff apps/api      # non-zero exit if the on-disk files drifted
docker build -f apps/api/Dockerfile .
```

## Surface

| Export | Purpose |
| --- | --- |
| `Docker.app` | The spec entrypoint; returns a `DockerApp` |
| `Docker.copy` | `builderArtifact({ src, dst, chown? })`, `workspaceSource(name)`, `workspaceSourceAll()`, `path({ src, dst, from?, chown? })` |
| `Docker.runtime` | `bun({ alpine? })`, `node({ alpine? })`; `alpine` defaults to `true` |
| `Docker.pm` | `bun()`, `npm()`, `pnpm()`, `yarn({ variant? })`; auto-detected from the root lockfile when omitted |
| `Docker.build` | `script(name)`, `command(argv)`, `none()`; when omitted, `script("build")` if the app has a `build` script, else `none()` |
| `Docker.healthcheck`, `Docker.user`, `Docker.platform` | `httpGet({ path, port, ... })` / `command({ argv, ... })`; `nonRoot({ uid?, gid?, name? })` / `root()`; `linuxAmd64()` / `linuxArm64()` |
| `DockerSpec`, `RunnerSpec`, `DevSpec`, `decodeDockerSpec`, `decodeDockerSpecSync` | Schemas and decoders for the spec; the atom schemas (`CopyAtom`, `RuntimeAtom`, `PackageManagerAtom`, `BuildAtom`, `HealthcheckAtom`, `UserAtom`, `PlatformAtom`) are exported too |
| `findRoot`, `allWorkspaces`, `closureOf`, `lookupWorkspace`, `workspaceDeps`, `detectPm`, `Workspace` | Workspace graph services |
| `lower({ spec, target })`, `prepareContext({ spec, target })`, `validateSpec({ spec, ctx })`, `buildIR({ spec, ctx, pm })`, `emit({ spec, target, specPath })` | Resolve the workspace context, validate the spec, and build the intermediate representation; `emit` runs the whole pipeline |
| `render`, `renderFile`, `renderHeader`, `extractHeader`, `HEADER_MARKER`, `sha256Hex` | Dockerfile rendering with a hashed header, and reading that header back; `sha256Hex` is the one from `@konfig.ts/core` |
| `bunPm`, `npmPm`, `pnpmPm`, `bunRuntime`, `nodeRuntime` | Package manager and runtime implementations |
| `isDockerApp`, `makeDockerApp`, `DockerAppTypeId`, `DockerApp`, `PACKAGE_NAME` | Spec identification helpers |

## Errors

Every failure the package can produce is a tagged error class exported from the package, and `AnyDockerError` is the union of the failures `emit` can raise. `SpecDecodeError`, `DockerWriteRefused`, and `DockerWriteError` are exported as well but are not part of that union.

| Error | When it is raised |
| --- | --- |
| `MonorepoRootNotFound` | No monorepo root could be found walking up from the starting directory |
| `WorkspaceNotFound` | The target app is not a workspace of the monorepo |
| `PackageJsonInvalid` | A workspace `package.json` is not valid JSON or does not match the expected shape |
| `UnsupportedYarnLinker` | Yarn Berry resolves to Plug'n'Play (`nodeLinker` absent or `pnp`); only `node-modules` and `pnpm` linkers are supported. A `yarnPath` release file is copied before `yarn install` |
| `PmRuntimeIncompatible` | The package manager and runtime image cannot work together: Bun needs `BunRuntime`; npm, pnpm and Yarn need `NodeRuntime` |
| `UnsupportedPm` | The package manager could not be determined: no `packageManager` field and either no recognized lockfile or several conflicting ones |
| `CircularWorkspaceDep` | The workspace graph contains a cycle |
| `EngineVersionMissing` | The app's `package.json` lacks the required `engines.*` entry |
| `EngineVersionInvalid` | An `engines.*` value is not an exact or major(.minor) version |
| `WorkspaceConfigInvalid` | `pnpm-workspace.yaml` is unreadable or malformed |
| `BuildScriptMissing` | The spec names a build script the app's `package.json` does not define |
| `WorkspaceSourceUnknown` | A `workspaceSource(name)` copy names a workspace outside the app's closure |
| `SharedRootFileMissing` | A file listed in `sharedRootFiles` does not exist at the monorepo root |
| `BunVersionUnsupported` | `runner.production` is set with Bun older than 1.2, which lacks `bun install --filter` |
| `SpecInvalid` | `emit` validates the spec first and fails with this when it is invalid: an env secret pattern, a port outside the valid range, or a health-check path that is not acceptable. Carries the validation `cause` |
| `SpecDecodeError` | Nothing in the package raises it; invalid specs fail with `SpecInvalid`. Kept for 0.4 compatibility |
| `DockerWriteRefused` | `konfig docker write` would overwrite a file that lacks the konfig header and `--force` was not given |
| `DockerWriteError` | `konfig docker write` failed to write a Dockerfile to disk |

<Aside type="caution">
Workspace `COPY` instructions only resolve from the monorepo root, so always pass the root as the Docker build context.
</Aside>

## Requirements

- `effect@^4.1.0` as a peer dependency (Effect 4).
- Depends on `@konfig.ts/core` and `yaml`.
- Runtime: Bun recommended; Node >= 23.6 works; Node 22.6 to 23.5 with `--experimental-strip-types`; `tsx` works.

Source and README: [packages/docker](https://github.com/DwieDave/konfig.ts/tree/main/packages/docker).
